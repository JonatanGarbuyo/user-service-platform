# Domain docs

This repository uses a single-context domain-documentation layout.

Before making changes, read:

- `CONTEXT.md`
- relevant ADRs under `docs/adr/`

Use the glossary vocabulary from `CONTEXT.md` consistently in issue titles, contracts, tests, code, and documentation. If a new concept cannot be named using existing vocabulary, resolve the terminology before proliferating synonyms.

If a proposed change contradicts an ADR, surface the conflict explicitly and create a replacement/superseding ADR rather than silently ignoring the existing decision.
